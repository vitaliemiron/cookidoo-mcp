# Cookidoo MCP brand guidelines

## Brand idea

Cookidoo MCP is the open bridge between human intent, AI assistance, and the
practical work of planning and cooking with Cookidoo.

## Mission

We automate the digital work around cooking for curious home cooks so they can
spend more time choosing, preparing, and enjoying food.

## Vision

A kitchen workflow where inspiration can become a clear recipe, a realistic
weekly plan, and an actionable shopping list without repetitive digital
administration.

## Positioning

For Cookidoo users who want more flexibility from their recipe workflow,
Cookidoo MCP is an unofficial open-source MCP server that lets an AI assistant
read and coordinate recipes, guided-cooking structure, shopping lists, images,
and meal plans. Unlike isolated scripts, it exposes a coherent set of validated
tools and monitors the external API for regressions.

## Primary message

From idea to dinner.

The homepage should explain the value in ordinary language first:

> Talk about what you want to eat. Let AI turn it into a clear Cookidoo
> recipe, place it in your week, and prepare the ingredient list.

Technical language belongs in documentation or optional `?` disclosures. Never
make a visitor understand MCP, API contracts, schemas, or UTF-16 before they can
understand what the product helps them do.

## Supporting messages

| Audience need | Message | Proof |
|---|---|---|
| Less repetitive work | Let one AI conversation coordinate the recipe workflow. | 16 purpose-built MCP tools |
| More useful inspiration | Adapt recipes from other languages and sources into clear Thermomix steps. | Structured ingredients, TTS, and modes |
| More intentional meals | Move from recipe ideas to a seven-day plan and shopping-list data. | Shopping and meal-plan tools |
| Confidence for beginners | Keep weighing, adding, and machine actions explicit and separate. | Enforced recipe-step validation |
| Trust in an unofficial API | Detect Cookidoo contract changes early. | 5 live API contracts and daily monitoring |

## Voice

We are:

- Human: begin with the life benefit, then explain the technology.
- Precise: make claims that can be traced to the repository.
- Optimistic: show what automation gives back without promising magic.
- Open: disclose that the project is unofficial and uses undocumented APIs.
- Practical: prefer clear verbs, examples, and next steps over abstract hype.

We sound like:

- “From idea to dinner.”
- “Talk about what you want to eat.”
- “Make the recipe yours, then place it in your week.”
- “Turn inspiration into a recipe you can actually cook.”
- “Let the repetitive steps connect themselves.”
- “The kitchen already has automation. The workflow around it can too.”

We do not sound like:

- “Revolutionary AI will transform your life.”
- “Guaranteed to save ten hours every week.”
- “Official Cookidoo integration.”

## Visual identity

- Direction: Swiss Modernism 2.0 with culinary warmth.
- Primary background: deep ink `#020617`.
- Elevated surface: navy `#0B1224`.
- Main text: frost `#F8FAFC`.
- Secondary text: slate `#B8C4D6`.
- Primary accent: saffron `#F2B84B`.
- Secondary accent: herb `#6EE7B7`.
- Technical accent: sky `#8BB7FF`.
- Heading type: JetBrains Mono.
- Body type: IBM Plex Sans.
- Grid: twelve columns on desktop, one column on mobile.
- Motion: short reveal and flow animations using only opacity and transforms.

Light theme is the default consumer experience:

- Background: warm cream `#FFFAF2`.
- Surface: white `#FFFFFF`.
- Foreground: charcoal `#1F2937`.
- Primary action: terracotta `#C2410C`.
- Strong action/label: deep terracotta `#9A3412`.
- Fresh accent: green `#047857`.
- Technical accent: blue `#1D4ED8`.

The light theme should feel like a familiar cooking and planning application:
warm, stable, immediately readable, and usable without technical knowledge.
Dark theme remains available for preference and developer-focused reading.

All pages must preserve visible focus states, WCAG AA contrast, keyboard
navigation, semantic heading order, and reduced-motion support.
